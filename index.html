CLI: xcl preflight — the environment checks without starting a game

preflight::checks already ran inside xcl run, but only as a side effect: a missing DXC, a Windows 10 box without the Agility SDK, or a GPU without mesh shaders only showed up after the title had already loaded for fifty seconds and presented nothing. Exposing the same run + print as a subcommand costs fifteen lines and one help block, and makes the check scriptable — exit 1 on any Error.

D3D12.X: time ExecuteCommandLists submissions (XCL_GPU_TIMING)

Every title submission passes through one function and nothing measured it. When a world load leaves the screen on a spinner and the watchdog kills the run, presents and frame_boundaries cannot tell "the CPU can't feed the GPU" from "the GPU never finishes". This clocks the submission, keeps the slowest in report.json with its command-list count, and warns above a threshold. It measures the CPU side of the call only — the field comment says so — because the call returns before the GPU is done.

The shader backend is finished, which is the part everyone assumed would be impossible. What is left is throughput and the TDR: either the CPU spends too long under a submission, or one dispatch exceeds the two-second Windows watchdog. Those are different bugs with different fixes, and right now nothing distinguishes them. That is the whole reason for the second patch.

Before you run a "gift"

A leaker posts hashes and tells you to verify. Verification only proves the file is the file — it says nothing about whether the file is safe, and a hash printed by the same person who made the file proves only that they can run sha256sum.

Two known fingerprints from the 2026 drops, so you can tell what you are holding:

ZIP  early_xmas.zip
7545a2f7fb4b399cf8850987f087ed9a4d8499ddb6d6c2d642fd60c27f569730

EXE  game_scarlett_master.exe
e95020b2fa4a721db3df59fdecf75621730ac559d8835252f6c3b658d5a08993
# Linux / macOS
sha256sum <file>

# Windows
certutil -hashfile <file> SHA256
  • Match is necessary, not sufficient. A hash match means you got the file the hash describes. It does not mean the file is clean.
  • Check the arithmetic. A console build that is 200 GB is not a 54 MB archive. A wrapper that unpacks and cracks something is not a game.
  • Look at what it drops. 7-Zip to extract, John the Ripper to crack a password, a dropped DLL beside a signed host binary — that is a toolchain, not a launcher.
  • One machine, one report. Self-reported results on a single GPU are a lead, not a fact. Ask for the second machine.

If you already ran one: treat the machine as compromised, change passwords from a different device, and move wallet funds before you do anything else on it.

On the race

Four days after the executable appeared, the projects that matter are the ones with a working product to their name rather than a roadmap. The layer above runs four retail titles; the GTA VI work is a test of it, not the reason it exists. That is the difference between a project that survives its target being taken down and one that does not — and the takedown is not hypothetical. Four DMCA notices landed on the day before launch, and the argument in them is that "bring your own files" is no defence.

The engineering will land. Whether the repository is still there when it does is a separate question with a worse answer.
